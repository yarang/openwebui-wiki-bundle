이 안내를 읽었으면 지금 바로 Bash 도구로 아래 명령을 실행해 파일을 만든다. '이해했습니다' 같은 글 답으로 끝내지 않고, Skill 을 다시 부르지 않는다.
워드(.docx) 문서 작업은 아래 명령만 쓴다. python 코드나 XML 을 직접 만들지 않는다.
명령은 매번 전체 경로 ~/.claude/skills/docx/scripts/docx 로 쓴다. D= 정의나 $D 는 쓰지 않는다.
작업 파일(md)과 결과 파일은 현재 작업 폴더에 ./이름 으로 만든다. skill 의 Base directory 는 명령이 있는 곳일 뿐이며 거기에는 아무것도 쓰지 않는다. Markdown 저장에 Write 도구를 쓰지 말고 Bash heredoc 을 쓴다.
새로 쓰기: 파일 이름은 사용자가 말한 파일 이름을 그대로 쓴다(아래 예시 이름은 예시일 뿐이다). 끝을 알리는 MD 는 혼자 한 줄에 쓰고, 변환 명령은 그 다음 줄에 쓴다(MD && 처럼 붙이지 않는다). Bash 한 번에 저장과 변환을 함께 한다.

```bash
cat > ./출장보고.md <<'MD'
# 출장 보고
## 1. 출장 개요
- 현장 점검 **완료**
  - 세부 항목
| 항목 | 값 |
| --- | --- |
| 교통비 | 1,000 |
MD
~/.claude/skills/docx/scripts/docx from-md ./출장보고.md
```

from-md 에는 md 경로 하나만 쓴다. 결과는 같은 이름의 .docx 파일로 생긴다(./출장보고.md → ./출장보고.docx).
쓸 수 있는 문법: # ~ ### 제목, - 목록과 1. 번호 목록(앞에 공백 두 칸이면 하위 항목), Markdown 표(| a | b |), **굵게**. 그 밖의 줄은 본문 문단이 된다.
사용자가 주지 않은 숫자·이름·날짜는 지어내지 않는다. 결과에 '경고 자리 표시' 줄이 있으면 무엇을 채워야 하는지 사용자에게 알린다.
읽기: ~/.claude/skills/docx/scripts/docx read ./파일.docx
출력 파일이 이미 있으면 거부되므로 다른 이름을 쓴다.
결과 첫 줄이 OK 면 그 경로를 사용자에게 알린다. ERROR 면 그 사유를 사용자에게 알린다.
한글(.hwpx) 문서는 이 스킬이 아니라 hwpx 스킬로 만든다.
자세한 옵션: ~/.claude/skills/docx/scripts/docx --help
